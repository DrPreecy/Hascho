# Deliverables and gates

## Meaning of status

- Drafted: content exists but has not been reviewed.
- Researched: relevant evidence and sources are recorded.
- Recommended: the agent proposes a direction with rationale.
- Decided: the Project Owner explicitly chose.
- Validated: the claim passed an agreed test.
- Implemented: the approved behavior exists.
- Measured: real operation produced data.

These statuses are not interchangeable.

## Gates

| Gate | Decision | Minimum evidence | Who decides |
| --- | --- | --- | --- |
| R0 | Approve research and conception plan | Scope, questions, sources, criteria, outputs | Project Owner |
| R1 | Accept research synthesis | Provenance, tensions, gaps, confidence | Project Owner |
| R2 | Approve usage and boundary model | Diverse scenarios and architecture drivers | Project Owner |
| R3 | Select system direction | Multiple coherent alternatives and trade-offs | Project Owner |
| R4 | Accept complete architecture for review | All required conceptual models and visuals | Project Owner |
| R5 | Accept critical-review corrections | Findings, dispositions, residual risks | Project Owner |
| R6 | Authorize implementation architecture | Final concept and explicit go-ahead | Project Owner |

No gate passes through silence or an agent's assumption.

## Visual deliverables

The final concept package should contain at minimum:

- end-to-end lifecycle and return paths;
- current-context or Control Room concept;
- assumption-evidence-decision flow;
- project, subproject, workstream, and thread boundaries;
- module activation logic;
- state and object relationship model;
- human and AI responsibility boundaries.

Use the visual form suited to the question. Do not force everything into one diagram.

## Completion criterion for conception

Conception is complete only when the required deliverables in docs/PRODUCT-BRIEF.md are internally consistent, source-backed where appropriate, critically reviewed, visually understandable, and explicitly approved.
